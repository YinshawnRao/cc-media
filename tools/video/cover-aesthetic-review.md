# 独立封面审美评估

本环节评估封面是否实现本期 brief 与 `design.md` 的表达目标，独立于 PROJECT、PUBLISHING 和 FINAL 技术检查。适用于本次制作或修改后交付的封面，包括 sandbox 测试片；不自动重审历史项目。由具备图像查看能力的 agent 实际审阅并留存独立报告，无需默认等待用户批准。

## 执行时机与输入

1. **整片渲染前初评**：完成无字视觉素材与 HTML 文字的实际合成后，导出完整封面、手机尺寸预览和目标平台裁剪。阅读本期主题、情绪、必要文案与用户明确偏好，再实际打开这些图片；不能只看提示词、HTML 源码或无字底图。
2. **单独记录结论**：写入项目 `qa/cover-aesthetic-review.md`，记录下方维度的具体观察、结论和实际查看的图像路径及 SHA-256。初评通过后继续渲染；明显不符合预期时进入仅封面返工。
3. **最终版本确认**：交付前查看最终封面、最终 MP4 第 0 帧及其手机裁剪，确认实际交付与初评版本一致。记录当前最终 MP4 SHA-256、首帧与预览文件哈希；有可见变化时重评受影响维度。独立封面图任务无 MP4 时如实记不适用。

每轮审阅记录实际 reviewer、`reviewer_kind=agent` 和带时区的时间。只有真实由人完成的审阅才记 `human`；agent 审美判断不是用户批准、点击率预测或发布授权。未实际看图、图片缺失或版本不匹配时，不能填通过。

## 评估维度

| 维度 | 根据实际封面回答的问题 |
| --- | --- |
| 主题与情绪 | 第一眼是否能认出主体、理解主题？视觉气质是否支持本期音乐内容和用户期望？ |
| 构图与视觉焦点 | 视线先落在哪里？主体、标题、留白是否平衡，是否存在拥挤、割裂或无意空洞？ |
| 字体与信息层级 | 文字是否准确，主次是否清楚，字体气质、字距与换行是否协调？手机尺寸下能否顺畅阅读？默认检查 HTML 信息文字与无字图像的合成。 |
| 配色与图文融合 | 明暗、色彩关系是否统一且有足够对比？人物边缘、背景与文字是否自然协调，是否有明显拼贴感、伪文字或生成瑕疵？ |
| 手机观看与完成度 | 缩小和裁剪后，主题是否仍有吸引力、主体与必要文字是否完整？装饰是否帮助表达，画面是否像已经完成的作品？ |

每项写清看到了什么、为何影响本期目标。直接依据本期 brief 判断，不设固定配色、字体、版式、元素数量或与旧作品的差异配额，也不把“我更喜欢另一种风格”作为退回理由。没有播放数据时，不把审美判断写成流量结论。

## 结论与处理

| 结论 | 使用条件 | 下一步 |
| --- | --- | --- |
| `PASS` | 实际图像符合本期表达目标，无明显影响整体观感或理解的问题；可保留轻微优化建议 | 初评后继续制作；完成最终版本确认后可随片交付 |
| `REWORK` | 存在明确、可见且明显偏离预期的问题，如主体与标题争抢焦点、严重失衡、关键文字难读、图文割裂或视觉气质与 brief 明显不符 | 写清问题位置、影响和具体修改方向，退回封面制作并复评 |
| `REVIEW_REQUIRED` | 尚未实际看图、目标或证据不足、图像与当前版本不匹配 | 先补齐本地证据或说明具体缺口，再审阅；不冒充通过，也不默认要求用户审批 |

这是定性的视觉评审，不用未经验证的自动分数或机械阈值代替看图。轻微偏好差异作为建议，不触发重做；明显问题需要修复后才能标为通过。每轮围绕已指出的问题修改、复评，已解决且无新明显问题时结束，避免为了换风格而反复推翻。

## 仅封面返工

- 修改前记录封面在时间轴中的实际区间和相关文件；保留非封面素材、歌单、文案、旁白、音乐、时间轴与正文视觉的当前版本及必要输入 SHA-256。封面只占开场的一部分时，不把整个 intro 当作返工范围。
- 允许修改封面图像、封面文字内容与排版、封面专用样式及对应首帧/封面区间合成。样式限定在封面节点下，避免改共享 CSS 影响正文。信息文字继续默认使用 HTML 与离线字体；需要重做图像时遵循 [封面图像生成流程](../../CONVENTIONS.md#封面图像生成流程)。
- 保持已确认的歌曲版本、顺序、展示窗口、旁白、配音、音乐、章节时长、正文画面和发布文案。不得以封面审美评估为由重新选歌、重写整片或重生成旁白。若所提修改必须超出封面范围，先缩小方案；确需改变核心 brief 时才向用户说明具体依赖。
- 重新导出封面并按原问题复评。涉及视频中已入片的封面时，重渲受影响的画面并重新 mux，复用原音轨和时间轴；工程只能整段或整片渲染时可以重建派生产物，但不得顺带改动其他内容。
- 复核非封面输入哈希、时间轴与片长，抽查封面结束处和正文代表帧，确认无样式泄漏或衔接变化。覆盖范围如实记录，抽查不能宣称逐帧一致。最终 MP4 改变后，按原项目适用路径刷新当前 SHA 的技术 QA；旧 SHA 的 FINAL PASS 不可沿用。这是封面替换所需的技术验证，不是对其他内容重新创作。

## 独立报告

在项目 `qa/cover-aesthetic-review.md` 按轮次保留以下记录。占位内容只作待填模板，不代表已完成评审；最终交付结论同时列出 `COVER AESTHETIC REVIEW` 的状态与 reviewer 身份、适用技术 QA 的状态。

```markdown
# 封面审美评估

## 第 <轮次> 轮

- 阶段：<渲染前初评 / 最终版本确认>
- 结论：REVIEW_REQUIRED
- reviewer_kind：<实际审阅后填写 agent 或 human>
- reviewer：<实际审阅者>
- reviewed_at：<实际审阅时间，含时区>
- 本期期望：<主题、情绪、必要文案及用户明确偏好>
- 封面范围：<时间区间及封面相关文件>
- 已查看证据：<完整封面、手机预览、目标裁剪的路径、尺寸、SHA-256；最终确认补充真实首帧与当前 MP4 SHA-256>

| 维度 | 具体观察与本期期望的关系 | 明显问题 / 轻微建议 / 符合预期 |
| --- | --- | --- |
| 主题与情绪 | <待审阅> | <待审阅> |
| 构图与视觉焦点 | <待审阅> | <待审阅> |
| 字体与信息层级 | <待审阅> | <待审阅> |
| 配色与图文融合 | <待审阅> | <待审阅> |
| 手机观看与完成度 | <待审阅> | <待审阅> |

- 结论依据：<为何通过或需要重做，不能只写好看或不好看>
- 仅封面修改清单：<具体问题、位置、修改方向；无需返工时写不适用>
- 复评结果：<逐项对应上一轮问题与新证据>
- 非封面保护核对：<修改前后输入哈希、时间轴与实际抽查结果；无修改时写不适用>
- 技术 QA 关联：<适用门禁、当前 SHA 和实际结果；尚未执行时如实写待执行>
```

本报告由实际视觉审阅产生，现有 `prepare_final_qa.py` 不会自动生成审美结论。`FINAL VIDEO QA: PASS` 只表示其机械检查通过；封面审美未审或需重做时，不能据此宣称整项制作已经验收完成。
