# 003 · 容祖儿 LIVE · 经典现场

本例以闭眼演唱、抬手和握麦的瞬间建立现场感，深蓝舞台托起亮黄色人物与文字。它补充了彩色演唱会海报的设计方向，也保留了从第一稿到第二稿调整手机裁剪的过程。

## 作品表达

原项目用六个现场版本串起 2005—2019，围绕“为什么要听这个版本”组织内容，没有排名。封面保留四组信息：

> 容祖儿
> LIVE
> 经典现场
> 2005—2019 · 六个版本

姓名建立身份，醒目的 LIVE 与演唱动作说明内容类型，“经典现场”点题，年份和版本数补充范围。真实表演参考中的粉紫马尾、亮黄色服装和闭眼抬手姿态，为配色与构图提供依据。

## 设计简述

| 选择 | 在本例中的作用 |
| --- | --- |
| 彩色演唱瞬间成为主体 | 闭眼、仰头、抬手和麦克风共同传递投入演唱的状态，直接回应“现场”主题。 |
| 姓名在上，人物居中，LIVE 与主题在下 | 身份、表演和内容类型形成纵向阅读顺序；文字避开面部、抬起的手掌与麦克风主体。 |
| 从黄色服装提取标题颜色 | 人物和文字共享亮色，画面形成整体；深蓝背景提供明暗与冷暖对比，粉紫马尾和侧光保留舞台色彩。 |
| 大字与简短信息组 | 姓名和 LIVE 在手机尺寸下仍有分量，中文主题及年段作为下一级信息，不再堆歌曲名、奖项或解释段。 |
| 舞台光束、薄雾与深色余白 | 光线把视线引向人物，上下空间容纳裁剪；不额外加入票根、边框或排名装饰。 |
| 第二轮整体收缩并延展背景 | 保留已有主体和文案，集中修正第一稿过于贴边的排布；减少中央 3:4 裁剪截字的问题。 |

以上是根据原项目记录与本次实际查看归纳的设计理由，不代表逐项用户评价。

## 两轮提示词与实际制作

本例的文字与人物一起由图像模型生成。原 HTML 直接展示 `cover-generated-v2.png`，没有另加封面标题；因此 [artwork.png](artwork.png) 是**含字完整设计图**。这与前两例“无字底图＋独立字体排版”的制作方式不同，两种方式均应按作品和实际成稿判断。

| 步骤 | 输入 → 输出 | 提示词的作用 |
| --- | --- | --- |
| 第一轮生成 | [实际人物参考](inputs/joey.png) → [第一轮图](inputs/first-pass.png) | 明确保留面部、表情、手势、服装、发型与麦克风；设定深蓝舞台、淡黄文字和四组文案，生成完整海报。 |
| 第二轮编辑（采用） | [第一轮图](inputs/first-pass.png) → [采用整图](artwork.png) | 保留身份和全部文案，缩小人物与文字整体、增加上下背景，并调整中央 3:4 裁剪安全区。 |
| 项目导出 | [采用整图](artwork.png) → [封面定稿](cover.png) | 将 941×1672 生成图居中覆盖至 1080×1920 画布；原项目从最终视频 0 秒抽帧导出封面。 |

[prompt.txt](prompt.txt) 按字节保留原文件：首段英文是第一轮请求，中间中文是第二轮说明与采用记录，`Adopted second edit prompt (verbatim)` 后为实际采用的第二轮英文提示词。第一轮图保留为第二轮的必要输入，不作为定稿展示。

原记录使用 `image_gen.imagegen`，未提供可核实的模型标识或精确生成时刻。本例也没有可验证的封面字体家族、字号和精确色值记录；可观察字形层级和颜色关系，不将正文工程字体误记为封面字体。

原提示词要求姓名顶边位于约 18% 高度、末行止于约 73%，这些是编辑目标。实际生成图没有严格逐像素遵守全部百分比；本例以实际封面和裁剪可读性为依据，不把提示词中的坐标当作已通过的测量结果。

## 如何借鉴，哪些应重新判断

- **可迁移的方法**：从具体表演动作和服装寻找构图与配色依据；让身份、人物和内容类型清楚分层；第一稿主体成立后，用后续编辑集中解决裁剪和可读性问题。
- **本期特定选择**：深蓝与亮黄、粉紫马尾、闭眼抬手、巨大 LIVE、这段年份和版本数。其他作品应按表演气质、主体动作和实际内容重新选择，不直接沿用海报外观或提示词。
- **适用问题**：以现场版本、歌手状态和演唱情绪为核心，参考图中已有清楚的表情与动作。多人合作、舞台全景或服装细节更重要时，应重新分配人物大小和文字区域。
- **生成文字的取舍**：这期四组文案在实际图中可读，不代表其他标题也能一次生成准确。后续仍要逐字核对姓名、年份与主题；是否采用独立文字排版按实际需要决定。
